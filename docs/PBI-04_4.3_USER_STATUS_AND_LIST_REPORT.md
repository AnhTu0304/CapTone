## 1. TỔNG QUAN VÀ KẾT QUẢ KIỂM TOÁN (AUDIT FINDINGS)

Trước khi tiến hành sửa mã nguồn, toàn bộ hệ thống đã được kiểm toán toàn diện:

1. **Cơ sở dữ liệu (PostgreSQL)**:
   - Kiểu ENUM `user_status` đã được thiết lập với 4 giá trị chuẩn: `'PENDING', 'ACTIVE', 'INACTIVE', 'SUSPENDED'`.
   - Bảng `users` lưu trữ hồ sơ người dùng (`id`, `email`, `full_name`, `avatar_url`, `phone`, `job_title`, `status`, `created_at`, `last_login_at`, `updated_at`, `deleted_at`).
   - Bảng `system_roles` và `user_system_roles` quản lý vai trò cấp hệ thống (`SUPER_ADMIN`, `SYSTEM_ADMIN`, `ADMIN`, `USER`).
   - Bảng `organizations`, `organization_members` và `roles` quản lý vai trò cấp tổ chức.

2. **Cơ chế thu hồi phiên và vô hiệu hóa Token tức thì (Immediate Token Revocation)**:
   - Trong `Main_backend/src/middlewares/auth.middleware.ts`, cơ chế bảo mật Fail-Closed động đã được triển khai thông qua `UserModel.findAuthStatus(decoded.id)`:
     ```typescript
     if (dbUser.status === 'SUSPENDED' || dbUser.status === 'INACTIVE') {
       return next(new ApiError(403, 'Tài khoản đã bị tạm khóa hoặc ngừng hoạt động'));
     }
     ```
   - Nhờ đó, ngay khi tài khoản bị chuyển sang `SUSPENDED`, mọi yêu cầu API tiếp theo sử dụng Access Token cũ đều bị chặn ngay lập tức với mã lỗi HTTP 403 Forbidden mà không phụ thuộc vào thời hạn của JWT Token.

3. **Tối ưu hóa truy vấn danh sách (Zero N+1 Queries)**:
   - Phương thức `UserModel.findMany` trước đây chưa nạp vai trò hệ thống và vai trò tổ chức trong cùng truy vấn.
   - Đã tối ưu hóa sử dụng `COALESCE(json_agg(...))` và `COALESCE(json_build_object(...))` trực tiếp trong PostgreSQL: gom nhóm vai trò hệ thống (`system_roles`) và vai trò tổ chức (`organization_roles`) chỉ trong 1 câu lệnh SELECT duy nhất.

## 2. CHI TIẾT CÁC ENDPOINT BACKEND HOÀN THIỆN

### 2.1. API Lấy danh sách người dùng (`GET /api/v1/users`)
- **Đường dẫn**: `GET /api/v1/users`
- **Xác thực**: Yêu cầu Bearer JWT Token của người dùng.
- **Phân quyền (RBAC)**: Chỉ `ADMIN` hoặc `SUPER_ADMIN` (`requireRoles('ADMIN', 'SUPER_ADMIN')`).
- **Hỗ trợ Query Params**:
  - `page`: Số trang (mặc định 1).
  - `limit`: Số bản ghi mỗi trang (mặc định 10, tối đa 100).
  - `search`: Tìm kiếm tổng hợp theo email, họ tên hoặc UUID.
  - `status`: Lọc theo trạng thái (`PENDING`, `ACTIVE`, `INACTIVE`, `SUSPENDED`).
  - `sort_by`: Sắp xếp theo `created_at`, `full_name`, `email`, `last_login_at`.
  - `order`: `ASC` hoặc `DESC`.
- **Dữ liệu trả về (Safe Contract)**:
  - Loại bỏ hoàn toàn `password_hash`, secret, token.
  - Bổ sung `system_roles: string[]` (danh sách vai trò hệ thống).
  - Bổ sung `organization_roles: object[]` (danh sách vai trò tổ chức).
  - Trả về metadata phân trang `pagination: { total, page, limit, totalPages }`.

### 2.2. API Khóa / Mở khóa tài khoản (`PATCH` / `PUT /api/v1/users/:id/status`)
- **Đường dẫn**:
  - `PATCH /api/v1/users/:id/status` (Chuẩn RESTful)
  - `PUT /api/v1/users/:id/status` (Alias tương thích ngược)
- **Xác thực**: Yêu cầu Bearer JWT Token.
- **Phân quyền (RBAC)**: Chỉ `ADMIN` hoặc `SUPER_ADMIN`.
- **Validation**:
  - `:id` phải là UUID hợp lệ.
  - `body.status` chỉ chấp nhận giá trị `'ACTIVE'` (để mở khóa) hoặc `'SUSPENDED'` (để khóa).
- **Quy tắc nghiệp vụ bảo mật nghiêm ngặt**:
  1. **Self-Lock Prevention**: Quản trị viên không thể tự khóa tài khoản của chính mình (`operatorId === targetUserId` -> Trả về `400 Bad Request: "Không thể tự thay đổi trạng thái hoặc khóa tài khoản của chính mình"`).
  2. **Target Existence**: Trả về `404 Not Found` nếu người dùng mục tiêu không tồn tại hoặc đã bị xóa mềm.
  3. **Duplicate State Check**: Nếu tài khoản đã ở trạng thái yêu cầu, trả về `400 Bad Request: "Tài khoản đã ở trạng thái tạm khóa/hoạt động"`.
  4. **Privilege Protection (Phân cấp đặc quyền)**: `ADMIN` không được phép khóa hoặc mở khóa tài khoản của `SUPER_ADMIN` -> Trả về `403 Forbidden: "Quản trị viên (ADMIN) không có quyền thay đổi trạng thái của Super Admin"`. Chỉ `SUPER_ADMIN` mới có quyền quản lý tài khoản cấp cao.
  5. **Immediate Token Revocation**: Tài khoản chuyển sang `SUSPENDED` sẽ bị từ chối truy cập ở toàn bộ các endpoint bảo vệ ngay tức thì.
